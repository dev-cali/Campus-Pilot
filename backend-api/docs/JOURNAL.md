**Goal:** Close the open security gap `PIPELINE.md` assigns to Brian, using Supabase Auth for identity without making every request depend on Supabase.

**Files changed:** `auth.py` (new), `database.py`, `main.py`, `routers/{users,documents,chunks,questions,ingest}.py`, `tests/test_auth.py` (new), `tests/test_backend_crud.py`, `requirements-demo.txt`, `.env.example`, `docs/AUTH.md` (new), `backend-api/docs/JOURNAL.md`.

**Steps:**
1. Compared Supabase Auth against a hand-built JWT/API-key layer. Supabase Auth is an identity service; PyJWT is only a token-verification library, so the real choice is "who owns identities", not "which library". Chose Supabase Auth for identity and local JWT verification for access control, because the login UI already advertises Google/Facebook SSO and password reset, which would otherwise be hand-built.
2. Read the actual code before editing: every router defined its own `get_db`, so a dependency override in tests only reached one module at a time. Moved one `get_db` into `database.py` and had `main.py` and all five routers import it. Overrides now apply application-wide with a single key.
3. Wrote `auth.py`: `HTTPBearer(auto_error=False)` so a missing header is 401 rather than FastAPI's 403; `jwt.decode` with an explicit `algorithms=["HS256"]`, `audience="authenticated"`, optional `issuer`, and `require=["exp", "sub", "aud"]`; verified `email` claim mapped onto `users.email` case-insensitively; `require_staff` using `users.role`. The secret is read per request, so importing the app never needs it, and a missing secret returns 503 instead of allowing access.
4. Applied the access matrix: reads need any signed-in user, mutations and `/ingest/chunk` need staff, `/test-ai` needs staff, `/departments` needs a signed-in user, `GET /` stays public. `GET /users` and `GET /questions` are staff-only because they expose other people's emails and queries.
5. Hardened two related things in `main.py`: CORS now reads `ALLOWED_ORIGINS` (default `http://localhost:3000`) instead of `["*"]` with credentials, and `/test-ai` logs provider errors server-side and returns a neutral 503 instead of `detail=str(e)`.
6. `POST /questions` now forces `user_id` to the caller for non-staff, so a student cannot attribute a question to someone else. Staff may still record for another user.
7. Added `PyJWT==2.15.1` to `requirements-demo.txt`. It was already in `.venv` as a transitive dependency of the `supabase` package, but CI installs only `requirements-demo.txt`, so without the pin `auth.py` would fail to import there.
8. Added `tests/test_auth.py` (28 tests). Tokens are minted with a throwaway test secret, so the suite is offline and never contacts Supabase or a paid provider.
9. Added one dependency override in `tests/test_backend_crud.py` so the existing CRUD tests act as staff; the auth rules themselves are covered in the new file.
10. Wrote `docs/AUTH.md`: configuration, token contract, access matrix, error behaviour, and the known gaps.

**Problems hit:**

### Task: Fix the four defects found by probing - 2026-11-03
